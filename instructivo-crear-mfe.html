Arquitectura del proyecto

Entiende el patrón antes de escribir código

💡
Idea central: el host (puerto 3000) muestra un <iframe> que apunta al MFE (ej. puerto 3003). El MFE detecta si está dentro del iframe y oculta su propia barra de navegación, comportándose como una sección embebida. Fuera del iframe (acceso directo) muestra su propio header.

🏠 Host (puerto 3000)

Dashboard principal. Tiene su propio Sidebar y TopBar. Cada módulo MFE vive en una ruta como /dashboard/products y renderiza un iframe.

📦 MFE (puerto 3003, 3004…)

Aplicación Next.js independiente. Tiene su propio código, páginas CRUD, y se comunica con las APIs del host vía NEXT_PUBLIC_HOST_URL.

🗄️ API en el Host

Las APIs viven en el host (/api/products, etc.) con cabeceras CORS para que el MFE pueda llamarlas desde otro origen.

🔗 Sidebar con mfe: true

Los links a módulos MFE usan <a> nativo en vez de <Link> de Next.js, para forzar un request HTTP completo y que el iframe se cargue correctamente.

📁
Estructura de carpetas del proyecto

01

Paso 1 – Modelo de Base de Datos

Define la estructura de los datos con Mongoose en el Host

✅
El modelo vive en el Host, no en el MFE. La razón: el Host es el único que tiene acceso a MongoDB. El MFE accede a los datos a través de la API del Host.
📄
Crea el archivo del modelo
Ejemplo: Módulo Productos
app/src/models/Product.ts 
import mongoose, { Schema, models } from "mongoose";

// 1. Define los campos y sus tipos
const ProductSchema = new Schema(
  {
    name:     { type: String, required: [true, "El nombre es requerido"], trim: true },
    category: { type: String, enum: ["DeFi", "NFT", "Layer1", "Layer2", "Otro"], default: "Otro" },
    symbol:   { type: String, required: true, uppercase: true, trim: true },
    price:    { type: Number, required: true, min: 0 },
    stock:    { type: Number, default: 0, min: 0 },
    status:   { type: String, enum: ["active", "inactive"], default: "active" },
  },
  { timestamps: true }  // agrega createdAt y updatedAt automáticamente
);

// 2. Exporta el modelo (el patrón evita duplicar modelos en hot-reload)
export const Product = models.Product || mongoose.model("Product", ProductSchema);
⚠️
Importante: siempre usa el patrón models.X || mongoose.model("X", Schema). Esto evita que Next.js intente registrar el modelo dos veces durante el hot-reload en desarrollo, lo que causaría el error "Cannot overwrite model once compiled".
1
Crea la carpeta si no existe
Los modelos van en app/src/models/. Cada modelo es un archivo TypeScript separado.
2
Define los tipos de datos
Tipos disponibles: String, Number, Boolean, Date. Usa enum para limitar los valores posibles. Usa required para campos obligatorios.
3
Activa timestamps
Añadir { timestamps: true } en el segundo argumento crea automáticamente los campos createdAt y updatedAt.

Paso 2 – Rutas API en el Host

Crea los endpoints REST con soporte CORS para el MFE

ℹ️
El MFE corre en un puerto diferente (ej. 3003). El navegador bloquea las peticiones cross-origin por seguridad. Para evitarlo, agrega cabeceras CORS en tus APIs.
⚡
Ruta principal: GET todos + POST crear
app/api/products/route.ts 
import { NextRequest, NextResponse } from "next/server";
import connectMongo from "@/app/src/lib/mongodb";
import { Product } from "@/app/src/models/Product";

// Cabeceras CORS — permiten que el MFE acceda a esta API
const CORS_HEADERS = {
  "Access-Control-Allow-Origin": process.env.NEXT_PUBLIC_PRODUCTS_MFE_URL ?? "http://localhost:3003",
  "Access-Control-Allow-Methods": "GET, POST, PUT, DELETE, OPTIONS",
  "Access-Control-Allow-Headers": "Content-Type, Authorization",
};

// Responde a peticiones "preflight" del navegador (requerido para CORS)
export async function OPTIONS() {
  return new NextResponse(null, { status: 204, headers: CORS_HEADERS });
}

export async function GET() {
  await connectMongo();
  const products = await Product.find().sort({ createdAt: -1 }).lean();
  return NextResponse.json(products, { headers: CORS_HEADERS });
}

export async function POST(req: NextRequest) {
  await connectMongo();
  const body = await req.json();
  const product = await Product.create(body);
  return NextResponse.json(product, { status: 201, headers: CORS_HEADERS });
}
⚡
Ruta por ID: GET uno + PUT actualizar + DELETE eliminar
app/api/products/[id]/route.ts 
export async function PUT(
  req: NextRequest,
  { params }: { params: Promise<{ id: string }> }
) {
  await connectMongo();
  const { id } = await params;          // Next.js 15: params es una Promise
  const body = await req.json();
  const product = await Product.findByIdAndUpdate(id, body, {
    new: true,           // devuelve el documento actualizado
    runValidators: true  // aplica las validaciones del schema
  }).lean();
  if (!product) return NextResponse.json({ error: "No encontrado" }, { status: 404 });
  return NextResponse.json(product, { headers: CORS_HEADERS });
}
⚠️
En Next.js 15, el objeto params de los route handlers es una Promise, no un objeto directo. Debes hacer await params antes de destructurarlo.

Paso 3 – Hook de datos con SWR

Crea dos versiones: una para el Host y otra para el MFE

ℹ️
¿Qué es SWR? Es una librería de React para obtener datos. Hace el fetch, guarda en caché, y refresca automáticamente. "SWR" viene de stale-while-revalidate: muestra datos en caché mientras verifica si hay nuevos.
🏠
Hook en el Host
URL relativa /api/...
// app/src/hooks/useProducts.ts
import useSWR from "swr";

const fetcher = (url: string) =>
  fetch(url).then(r => r.json());

export const useProducts = () => {
  const { data, error, isLoading, mutate } =
    useSWR<AppProduct[]>("/api/products", fetcher);
  return { products: data, loading: isLoading, error, mutate };
};
📦
Hook en el MFE
URL absoluta al host
// products-mfe/app/src/hooks/useProducts.ts
const HOST_URL =
  process.env.NEXT_PUBLIC_HOST_URL
  ?? "http://localhost:3000";

export const useProducts = () => {
  const { data, error, isLoading, mutate } =
    useSWR<AppProduct[]>(
      `${HOST_URL}/api/products`, fetcher
    );
  return { products: data, loading: isLoading,
            error, mutate };
};
💡
Diferencia clave: el hook del Host usa URL relativa (/api/products) porque corre en el mismo servidor. El hook del MFE usa URL absoluta (http://localhost:3000/api/products) porque es una aplicación separada.
🏷️
Tipo TypeScript del modelo
// Define exactamente los campos que devuelve MongoDB
export type AppProduct = {
  _id: string;
  name: string;
  category: "DeFi" | "NFT" | "Layer1" | "Layer2" | "Otro";
  symbol: string;
  price: number;
  stock: number;
  status: "active" | "inactive";
  createdAt: string;
  updatedAt: string;
};

Paso 4 – Página contenedora en el Host

Un simple iframe que apunta al MFE

✨
Esta es la parte más simple de todo el proceso. La página en el host no hace nada excepto mostrar un <iframe> que apunta al MFE. El MFE renderiza su contenido dentro del iframe, compartiendo el Sidebar y TopBar del host.
🖼️
Página contenedora del host
app/dashboard/products/page.tsx 
// La URL del MFE: en desarrollo es localhost, en producción usa variable de entorno
const MFE_URL = process.env.NEXT_PUBLIC_PRODUCTS_MFE_URL ?? "http://localhost:3003";

export default function ProductsPage() {
  return (
    <iframe
      src={`${MFE_URL}/dashboard/products`}
      title="Módulo de Productos"
      style={{
        width: "100%",
        height: "calc(100vh - 64px)",  // 64px = altura del TopBar del host
        border: "none",
        display: "block",
      }}
    />
  );
}
⚠️
La URL del src del iframe incluye el basePath: /dashboard/products. Con el basePath configurado en el MFE, la ruta raíz del MFE es exactamente http://localhost:3003/dashboard/products.

Paso 5 – Crear el proyecto MFE

Configuración inicial del proyecto Next.js independiente

1
Crea la carpeta del MFE
Al mismo nivel que dashboard-nextjs/, crea una carpeta nueva: products-mfe/. Dentro crearás todos los archivos manualmente (como se muestra a continuación).
2
Crea el package.json
Define el nombre, el puerto (con -p 3003) y las dependencias. Necesitas: next, react, react-dom, swr.
📦
package.json del MFE
products-mfe/package.json 
{
  "name": "products-mfe",
  "scripts": {
    "dev":   "next dev -p 3003",   // ← puerto único para cada MFE
    "build": "next build",
    "start": "next start -p 3003"
  },
  "dependencies": {
    "next": "15.3.2",
    "react": "^19.0.0",
    "react-dom": "^19.0.0",
    "swr": "^2.3.3"
  }
}
⚙️
next.config.ts — el basePath es crítico
products-mfe/next.config.ts 
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  basePath: "/dashboard/products",
  // Descomenta en producción con Docker:
  // output: "standalone",
};

export default nextConfig;
ℹ️
El basePath hace que todas las rutas del MFE queden bajo /dashboard/products. Así, la página raíz (app/page.tsx) es accesible en http://localhost:3003/dashboard/products, y app/new/page.tsx en http://localhost:3003/dashboard/products/new.
🌍
Variables de entorno del MFE
products-mfe/.env.local 
# URL del host donde viven las APIs
NEXT_PUBLIC_HOST_URL=http://localhost:3000

# En producción cambia esto por la URL real del host:
# NEXT_PUBLIC_HOST_URL=https://app.tudominio.com
3
Crea tsconfig.json, postcss.config.mjs y tailwind.config.ts
Cópialos del proyecto transactions-mfe cambiando solo el nombre. Lo importante en tsconfig es el path alias: "@/*": ["./*"].
4
Instala dependencias
Desde la carpeta del MFE ejecuta: npm install. Esto crea node_modules/ y package-lock.json.

Paso 6 – EmbeddedShell: el cerebro de la integración

El componente que detecta si estamos dentro de un iframe

🧠
¿Por qué es necesario? Sin este componente, si abres el MFE directamente en el navegador no verías ninguna barra de navegación. Con EmbeddedShell, el MFE se comporta correctamente en ambos contextos: embebido en el host o accedido directamente.
🔍
EmbeddedShell.tsx — detecta el iframe
app/components/EmbeddedShell.tsx 
"use client";  // necesario porque usa window (solo disponible en el browser)

import { useState, useEffect } from "react";

export default function EmbeddedShell({
  children
}: {
  children: React.ReactNode
}) {
  const [isEmbedded, setIsEmbedded] = useState(false);

  useEffect(() => {
    try {
      // Si window.self !== window.top, estamos dentro de un iframe
      setIsEmbedded(window.self !== window.top);
    } catch {
      // Error cross-origin = también estamos embebidos
      setIsEmbedded(true);
    }
  }, []);

  if (isEmbedded) {
    // Modo iframe: solo el contenido, sin chrome propio
    return <div style={{ backgroundColor: "var(--background)", minHeight: "100vh" }}>{children}</div>;
  }

  // Modo standalone: muestra un header básico
  return (
    <div style={{ minHeight: "100vh" }}>
      <header style={{ height: 56, backgroundColor: "#fff", borderBottom: "1px solid #e5e7eb" }}>
        <span>MFE Productos — modo standalone</span>
      </header>
      <main>{children}</main>
    </div>
  );
}
📐
Úsalo en el layout del MFE
app/layout.tsx 
import EmbeddedShell from "./components/EmbeddedShell";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="es">
      <body>
        <EmbeddedShell>{children}</EmbeddedShell>
      </body>
    </html>
  );
}

Paso 7 – Páginas del MFE

Lista, crear y editar. Navegan con el hook del MFE

Archivo en el MFE URL resultante Función
app/page.tsx /dashboard/products Lista todos los productos con acciones Editar y Eliminar
app/new/page.tsx /dashboard/products/new Formulario para crear un nuevo producto
app/edit/[id]/page.tsx /dashboard/products/edit/:id Formulario para editar un producto existente
🗂️
La carpeta app/ del MFE funciona igual que en cualquier proyecto Next.js. El basePath en next.config.ts añade automáticamente el prefijo /dashboard/products a todas las rutas. Los componentes <Link href="/new"> navegarán correctamente a /dashboard/products/new.
📋
Estructura de la página de lista
app/page.tsx 
"use client";

import Link from "next/link";
import { useProducts, deleteProduct } from "@/app/src/hooks/useProducts";

export default function ProductsListPage() {
  const { products, loading, error, mutate } = useProducts();

  const handleDelete = async (id: string) => {
    if (!confirm("¿Eliminar este producto?")) return;
    await deleteProduct(id);
    mutate();  // re-fetcha los datos para actualizar la lista
  };

  if (loading) return <p>Cargando…</p>;
  if (error)   return <p>Error al cargar</p>;

  return (
    <div>
      <Link href="/new">Nuevo Producto</Link>  // → /dashboard/products/new
      {products?.map(p => (
        <div key={p._id}>
          {p.name}
          <Link href={`/edit/${p._id}`}>Editar</Link>
          <button onClick={() => handleDelete(p._id)}>Eliminar</button>
        </div>
      ))}
    </div>
  );
}

Paso 8 – Agregar al Sidebar del Host

El link al módulo MFE necesita usar <a> nativo, no <Link> de Next.js

🚫
Problema conocido: Si usas <Link> de Next.js para navegar al módulo MFE, el iframe no se cargará. Esto ocurre porque <Link> hace navegación client-side sin recargar la página, y el componente ProductsPage (con el iframe) nunca monta.
✅
Solución: usa una etiqueta <a href="..."> nativa. Esto fuerza una recarga completa de la página, el host renderiza la ruta correcta y el iframe se monta correctamente.
🗂️
Agregar el item al array de navegación
app/src/components/organisms/Sidebar/index.tsx 
// 1. El tipo NavItem incluye la bandera "mfe"
type NavItem = {
  href: string;
  label: string;
  icon: React.ReactNode;
  mfe?: boolean;  // ← true = usar <a> nativo
};

// 2. Agrega tu módulo al array con mfe: true
const NAV_MANAGEMENT: NavItem[] = [
  { href: "/dashboard/users",    label: "Usuarios",    icon: <IconUsers /> },
  { href: "/dashboard/transactions", label: "Transacciones", icon: <IconTx />, mfe: true },
  { href: "/dashboard/products",  label: "Productos",    icon: <IconBox />, mfe: true },
  { href: "/dashboard/alerts",    label: "Alertas",      icon: <IconBell />, mfe: true },
];

// 3. El componente NavGroup decide qué elemento renderizar
return item.mfe ? (
  <a href={item.href} ...>{inner}</a>   // ← recarga completa
) : (
  <Link href={item.href} ...>{inner}</Link>  // ← navegación SPA
);
