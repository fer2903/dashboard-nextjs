Paso 1 – Configurar AWS SES

El servicio de envío de emails de AWS

📧
AWS SES (Simple Email Service) es el servicio de emails de AWS. Es económico (primer 62,000 emails/mes gratis si se envían desde EC2/Lambda) y muy confiable. La configuración inicial toma unos minutos.
⚠️
Sandbox mode: por defecto SES está en modo sandbox. Solo puedes enviar emails a direcciones verificadas. Para enviar a cualquier dirección debes solicitar salir del sandbox (Paso 10).
1
Selecciona la región correcta
Ve a AWS Console → SES. Usa la misma región donde está tu Lambda (ej. us-east-1). SES no está disponible en todas las regiones.
2
Abre el panel de SES
En el menú lateral verás: Verified identities, Configuration sets, Sending statistics. Empieza por "Verified identities".
02

Paso 2 – Verificar identidades de email

SES requiere verificar el email remitente

✉️
Verificar email o dominio
1
SES → Verified identities → Create identity
Tienes dos opciones: verificar un email individual (más rápido, para dev) o un dominio completo (para producción, permite enviar desde cualquier @tudominio.com).
2
Opción A: Email individual
Identity type: Email address. Email: reportes@tudominio.com. AWS te enviará un email de confirmación. Haz clic en el enlace.
3
Opción B: Dominio completo (recomendado)
Identity type: Domain. Domain: tudominio.com. AWS te dará registros TXT/CNAME que debes agregar en tu DNS (Route53, Cloudflare, etc.). La verificación tarda ~24-72h.
4
También verifica el email destinatario (en sandbox)
Mientras estés en sandbox, verifica también el email del destinatario (ej. admin@tudominio.com) siguiendo los mismos pasos.

Paso 3 – Permisos IAM para SES

Agrega los permisos al rol de Lambda

ℹ️
Si ya seguiste el instructivo de Lambda, el rol lambda-pdf-report-role ya tiene los permisos de SES. Si no, agrega esta política inline al rol.
🔑
Política IAM para SES
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ses:SendEmail",        // Enviar email simple
        "ses:SendRawEmail"      // Enviar email con adjuntos (MIME)
      ],
      "Resource": "arn:aws:ses:us-east-1:TU_ACCOUNT_ID:identity/tudominio.com"
    }
  ]
}

Reemplaza TU_ACCOUNT_ID con tu ID de cuenta de AWS (12 dígitos) y tudominio.com con tu dominio verificado.

Paso 5 – Módulo sendEmail.mjs

Envía el email con SES + link de descarga

📤
Módulo sendEmail con AWS SES
lib/sendEmail.mjs
import { SESClient, SendEmailCommand } from "@aws-sdk/client-ses";
import { buildEmailHtml } from "./emailTemplate.mjs";

const ses = new SESClient({ region: process.env.AWS_REGION ?? "us-east-1" });

/**
 * Envía el reporte por email con un link de descarga.
 *
 * @param {object} options
 * @param {string|string[]} options.to       - Destinatario(s)
 * @param {string}          options.downloadUrl - URL pre-firmada de S3
 * @param {number}          options.totalTransactions
 * @param {number}          options.totalAmount
 * @param {string}          [options.period]   - Descripción del período
 */
export async function sendReportEmail({
  to,
  downloadUrl,
  totalTransactions,
  totalAmount,
  period
}) {
  const toAddresses = Array.isArray(to) ? to : [to];
  const fromEmail = process.env.SES_FROM_EMAIL;

  if (!fromEmail) throw new Error("SES_FROM_EMAIL no está configurada");

  const html = buildEmailHtml({ totalTransactions, totalAmount, downloadUrl, period });

  const params = {
    Source: `Crypto Dashboard <${fromEmail}>`,
    Destination: { ToAddresses: toAddresses },
    Message: {
      Subject: {
        Data: `📊 Reporte de Transacciones — ${period ?? new Date().toLocaleDateString("es-MX")}`,
        Charset: "UTF-8",
      },
      Body: {
        Html: { Data: html, Charset: "UTF-8" },
        // Versión texto plano (fallback para clientes que no soportan HTML)
        Text: {
          Data: `Reporte de transacciones generado.
Total: ${totalTransactions} transacciones.
Descarga: ${downloadUrl}
El enlace expira en 24 horas.`,
          Charset: "UTF-8",
        },
      },
    },
  };

  const result = await ses.send(new SendEmailCommand(params));
  console.log("Email enviado. MessageId:", result.MessageId);
  return result;
}
📎
¿Enviar el PDF como adjunto? En lugar del link de descarga, puedes adjuntar el PDF directamente. Para eso usa SendRawEmail con formato MIME multipart. Ver la alternativa en el Paso 9 (Nodemailer) que simplifica esto.

Paso 6 – Handler final: PDF + Email

Integra todo: generación, S3 y envío de email

⚡
index.mjs actualizado con email
index.mjs
import { fetchTransactions } from "./lib/fetchTransactions.mjs";
import { generateTransactionsPdf } from "./lib/generatePdf.mjs";
import { uploadPdfToS3 } from "./lib/uploadToS3.mjs";
import { sendReportEmail } from "./lib/sendEmail.mjs";

export const handler = async (event) => {
  console.log("Iniciando generación y envío de reporte");

  try {
    const body = event.body ? JSON.parse(event.body) : {};

    // Destinatarios: del body o de variable de entorno
    const toEmails = body.emails
      ?? process.env.REPORT_RECIPIENTS?.split(",")
      ?? [];

    if (toEmails.length === 0) {
      throw new Error("No hay destinatarios configurados. Envía 'emails' en el body o configura REPORT_RECIPIENTS.");
    }

    // 1. Obtener transacciones
    const transactions = await fetchTransactions({
      startDate: body.startDate,
      endDate:   body.endDate,
    });

    // 2. Calcular totales para el email
    const totalAmount = transactions.reduce((s, t) => s + (t.amount ?? 0), 0);
    const period = body.startDate && body.endDate
      ? `${body.startDate} al ${body.endDate}`
      : new Date().toLocaleDateString("es-MX", { year: "numeric", month: "long", day: "numeric" });

    // 3. Generar PDF
    const pdfBuffer = await generateTransactionsPdf(transactions);

    // 4. Subir a S3
    const fileName = `transactions-${new Date().toISOString().slice(0,10)}-${Date.now()}.pdf`;
    const downloadUrl = await uploadPdfToS3(pdfBuffer, fileName);

    // 5. Enviar email a todos los destinatarios
    await sendReportEmail({
      to: toEmails,
      downloadUrl,
      totalTransactions: transactions.length,
      totalAmount,
      period,
    });

    console.log(`✅ Reporte enviado a: ${toEmails.join(", ")}`);

    return {
      statusCode: 200,
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        success: true,
        message: `Reporte enviado a ${toEmails.length} destinatario(s)`,
        fileName,
        downloadUrl,
        totalTransactions: transactions.length,
        recipients: toEmails,
      }),
    };

  } catch (error) {
    console.error("Error:", error);
    return {
      statusCode: 500,
      body: JSON.stringify({ error: error.message }),
    };
  }
};

Paso 7 – Envío automático diario

EventBridge trigger para envío programado

⏰
Con EventBridge puedes programar la Lambda para que se ejecute automáticamente todos los días a una hora específica y envíe el reporte sin intervención manual.
1
Lambda → Add trigger → EventBridge
Selecciona "Create a new rule". Rule name: daily-transactions-report. Rule type: Schedule expression.
2
Expresión cron
cron(0 8 * * ? *) → ejecuta todos los días a las 8am UTC (2am México, 3am Argentina).
Para personalizar: cron(0 14 * * ? *) = 2pm UTC = 8am México.
3
Payload del trigger
En "Configure input" → Constant JSON text: {"source": "eventbridge-scheduled"}. Tu handler lo detecta y envía a los destinatarios de REPORT_RECIPIENTS.
🕐
Referencia de expresiones cron en AWS
ExpresiónCuándo se ejecuta
cron(0 8 * * ? *)Todos los días a las 8:00 UTC
cron(0 8 ? * MON *)Cada lunes a las 8:00 UTC
cron(0 8 1 * ? *)El día 1 de cada mes a las 8:00 UTC
rate(1 day)Cada 24 horas desde la creación
rate(12 hours)Cada 12 horas

import { NextRequest, NextResponse } from "next/server";

export async function POST(req: NextRequest) {
  const { emails } = await req.json();

  const response = await fetch(process.env.LAMBDA_PDF_URL!, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ emails }),
  });

  const data = await response.json();
  return NextResponse.json(data, { status: response.status });
}
🔘
Componente en el MFE de Transacciones
"use client";
import { useState } from "react";

const HOST_URL = process.env.NEXT_PUBLIC_HOST_URL ?? "http://localhost:3000";

export function SendReportEmailButton() {
  const [loading, setLoading] = useState(false);
  const [sent, setSent] = useState(false);

  const handleSend = async () => {
    const emailInput = prompt("Ingresa el email destinatario:");
    if (!emailInput) return;

    setLoading(true);
    try {
      const res = await fetch(`${HOST_URL}/api/reports/send-email`, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ emails: [emailInput] }),
      });
      if (res.ok) {
        setSent(true);
        setTimeout(() => setSent(false), 3000);
      }
    } finally {
      setLoading(false);
    }
  };

  return (
    <button onClick={handleSend} disabled={loading}
      style={{ background: sent ? "#059669" : "#0284c7", color: "#fff",
               padding: "8px 16px", borderRadius: "8px", border: "none" }}>
      {loading ? "Enviando…" : sent ? "✓ Enviado" : "✉ Enviar por Email"}
    </button>
  );
}

Alternativa: Nodemailer + SMTP / Gmail

Si no quieres usar SES o prefieres adjuntar el PDF

📎
Nodemailer facilita el envío con adjuntos. Funciona con cualquier SMTP: Gmail (para dev), Outlook, SendGrid, Mailgun o el propio SES vía SMTP.
📧
sendEmail con Nodemailer + adjunto PDF
lib/sendEmailNodemailer.mjs
import nodemailer from "nodemailer";
import { buildEmailHtml } from "./emailTemplate.mjs";

// Configura el transporter (usa variables de entorno)
const transporter = nodemailer.createTransporter({
  host:   process.env.SMTP_HOST ?? "email-smtp.us-east-1.amazonaws.com", // SES SMTP
  port:   587,
  secure: false,
  auth: {
    user: process.env.SMTP_USER,   // SMTP username (no es tu email)
    pass: process.env.SMTP_PASS,   // SMTP password
  },
});

export async function sendReportEmailWithAttachment({
  to, pdfBuffer, fileName, totalTransactions, totalAmount, period
}) {
  const html = buildEmailHtml({ totalTransactions, totalAmount, period,
                              downloadUrl: "(adjunto)" });

  await transporter.sendMail({
    from: `"Crypto Dashboard" <${process.env.SES_FROM_EMAIL}>`,
    to: Array.isArray(to) ? to.join(",") : to,
    subject: `📊 Reporte de Transacciones — ${period ?? "Hoy"}`,
    html,
    attachments: [
      {
        filename: fileName,
        content: pdfBuffer,
        contentType: "application/pdf",
      },
    ],
  });
}
⚠️
Para usar SES SMTP: IAM → Users → Create user → Attach policy AmazonSesSendingAccess → Security credentials → Create SMTP credentials. Esto genera usuario/contraseña SMTP específicos para SES.

Salir del Sandbox de SES (Producción)

Para enviar emails a cualquier dirección

🔒
En Sandbox mode solo puedes enviar a emails verificados. Para producción necesitas solicitar acceso de producción.
1
SES → Account dashboard → Request production access
Haz clic en el botón "Request production access".
2
Completa el formulario
Mail type: Transactional. Website URL: tu dominio. Use case description: explica que envías reportes automáticos a usuarios de tu plataforma. Expected sending volume: número de emails diarios.
3
Espera la aprobación
AWS revisa la solicitud en 24-48h. Recibirás un email de confirmación. Una vez aprobado, puedes enviar a cualquier dirección.
