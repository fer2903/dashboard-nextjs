·Concepto: paquete dual

El MFE se convierte en un paquete dual:

  • App Next.js standalone en su puerto (3001 / 3003 / 3004) para desarrollo aislado. npm run dev sigue funcionando igual.
  • Librería npm que exporta las páginas/componentes como React, para que el host las importe directo (sin iframe, sin multi-zone).

Las páginas viven en app/ como ya lo hacen. Un lib/index.ts las re-exporta. tsup compila ese entry point a dist/ con ESM + CJS + tipos. Tailwind se compila aparte a dist/styles.css.

Clave: next, react y react-dom se mueven a peerDependencies. El host los provee; el paquete no los duplica.

1Reescribir package.json

Reemplaza el package.json completo del MFE. Ajusta name, description y puerto según el MFE.

{
  "name": "transactions-mfe",
  "version": "1.0.0",
  "description": "MFE de Transacciones — npm + standalone",
  "license": "MIT",
  "type": "module",

  // Entry points
  "main":    "./dist/index.cjs",
  "module":  "./dist/index.js",
  "types":   "./dist/index.d.ts",
  "exports": {
    ".": {
      "types":   "./dist/index.d.ts",
      "import":  "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./styles.css": "./dist/styles.css"
  },

  // Solo se publica /dist + README + LICENSE
  "files": ["dist", "README.md", "LICENSE"],
  "sideEffects": ["**/*.css"],
  "publishConfig": { "access": "public" },

  "scripts": {
    "dev":            "next dev -p 3001",
    "build":          "next build",
    "start":          "next start -p 3001",
    "build:lib":      "tsup && npm run build:css",
    "build:css":      "tailwindcss -i ./app/globals.css -o ./dist/styles.css --minify",
    "prepublishOnly": "npm run build:lib",
    "pack:dry":       "npm pack --dry-run"
  },

  // Lo provee el host
  "peerDependencies": {
    "next":      ">=15.0.0",
    "react":     ">=19.0.0",
    "react-dom": ">=19.0.0"
  },

  // Solo para desarrollo y build local
  "devDependencies": {
    "next": "^16.2.4",
    "react": "19.2.4",
    "react-dom": "19.2.4",
    "tsup": "^8.3.5",
    "@tailwindcss/cli": "^4.0.0",
    "@tailwindcss/postcss": "^4",
    "tailwindcss": "^4",
    "typescript": "^5",
    "@types/node": "^20",
    "@types/react": "^19",
    "@types/react-dom": "^19"
  }
}
Quitar "private": true es obligatorio. Mientras esté presente, npm publish rechaza el paquete.

2Crear lib/index.ts

Este archivo re-exporta las páginas del App Router como componentes React. Es lo único que entra al bundle de la librería.

// lib/index.ts
export { default as TransactionsListPage } from "../app/page";
export { default as NewTransactionPage }   from "../app/new/page";
export { default as EditTransactionPage }  from "../app/edit/[id]/page";
export { default as Sidebar }              from "../app/components/Sidebar";
export { default as EmbeddedShell }        from "../app/components/EmbeddedShell";

3Crear tsup.config.ts

import { defineConfig } from "tsup";

export default defineConfig({
  entry: ["lib/index.ts"],
  format: ["esm", "cjs"],
  dts: true,
  sourcemap: true,
  clean: true,
  splitting: false,
  treeshake: true,
  target: "es2020",
  // El host provee estas libs en runtime
  external: [
    "react",
    "react-dom",
    "react/jsx-runtime",
    "next",
    "next/link",
    "next/navigation",
  ],
  esbuildOptions(options) {
    // Preserva "use client" para que Next del host lo reconozca
    options.banner = { js: '"use client";' };
    options.jsx = "automatic";
  },
});

4Crear tsconfig.build.json

Necesario para emitir los .d.ts (el tsconfig.json principal tiene noEmit: true).

{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "noEmit": false,
    "declaration": true,
    "declarationDir": "dist",
    "outDir": "dist",
    "emitDeclarationOnly": true
  },
  "include": ["lib/**/*", "app/**/*"],
  "exclude": ["node_modules", "dist", ".next"]
}

6README y LICENSE

El README debe documentar:

  • Cómo instalarlo (npm install <nombre>)
  • Qué componentes exporta (tabla)
  • Qué variables de entorno necesita el host (NEXT_PUBLIC_API_URL)
  • Cómo levantarlo standalone (npm run dev)
  • Cómo empaquetar (npm run build:lib) y publicar (npm publish)

Para LICENSE usa MIT estándar (cualquier generador sirve).

7Build y publicación

# 1. Instalar nuevas dependencias
npm install

# 2. Compilar la librería (genera /dist)
npm run build:lib

# 3. Verificar qué se va a publicar (no sube nada)
npm run pack:dry

# 4. Publicar al registry configurado
npm publish
#   prepublishOnly correrá build:lib automáticamente
Salida esperada de pack:dry: debe listar solo dist/index.js, dist/index.cjs, dist/index.d.ts, dist/styles.css, package.json, README.md y LICENSE. Si aparece app/ o .next/, el .npmignore no está correcto.

·Consumirlo desde el host

Una vez publicado:

# En dashboard-nextjs
npm install transactions-mfe
// app/dashboard/transactions/page.tsx
import { TransactionsListPage } from "transactions-mfe";
import "transactions-mfe/styles.css";

export default function Page() {
  return <TransactionsListPage />;
}

El iframe + rewrites multi-zone del host ya no son necesarios. El MFE corre dentro del proceso del host como cualquier componente React.

·Diferencias para cada MFE

products-mfe puerto 3003

  • "name": "products-mfe"
  • Scripts dev / start: usar -p 3003
  • lib/index.ts: exportar las páginas y componentes que existan en app/ (revisa los archivos antes de escribir el index)
  • Si usa Tailwind v3 (en lugar de v4 como transactions): el script build:css sigue siendo válido con tailwindcss de v3 — el binario tiene la misma interfaz -i / -o
  • Dependencias propias (ej. swr): si son usadas por los componentes exportados, agregarlas como dependencies (no peer)

alerts-mfe puerto 3004

  • "name": "alerts-mfe"
  • Scripts dev / start: usar -p 3004
  • Mismo tratamiento que products: revisa qué hay en app/, exporta cada page como named export, e incluye dependencias propias como dependencies
Atención con dependencias. Si un MFE usa swr, @tanstack/react-query, etc., elige una de dos opciones:
· Si el host también las usa con la misma versión → ponlas como peerDependencies para evitar duplicación.
· Si son específicas del MFE → dependencies.
