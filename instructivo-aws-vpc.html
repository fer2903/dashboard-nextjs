¿Qué es una VPC y para qué sirve?

Conceptos clave antes de empezar

💡
VPC (Virtual Private Cloud) es tu red privada dentro de AWS. Es como tener tu propio datacenter virtual, aislado del resto de internet y de otras cuentas de AWS. Todo lo que creas en AWS (servidores EC2, bases de datos RDS, funciones Lambda) vive dentro de una VPC.

🌐 VPC

Red privada virtual. Define el rango de IPs que puedes usar (CIDR block). Ej: 10.0.0.0/16 da 65,536 IPs posibles.

🔲 Subnet

Segmento de la VPC. Puede ser pública (con acceso a internet) o privada (sin acceso directo). Se asigna a una Availability Zone.

🚪 Internet Gateway (IGW)

Puerta de entrada a internet. Se adjunta a la VPC y permite que las subnets públicas envíen y reciban tráfico de internet.

🔄 NAT Gateway

Permite que los recursos en subnets privadas salgan a internet (para descargar paquetes, llamar APIs externas) sin ser accesibles desde fuera.

🗺️ Route Table

Tabla de rutas. Define hacia dónde va el tráfico. Cada subnet se asocia con una route table.

🛡️ Security Group

Firewall virtual a nivel de instancia. Controla qué tráfico puede entrar y salir de un recurso específico (EC2, Lambda, RDS).

Paso 1 – Crear la VPC

La red privada principal

1
Accede a la consola de AWS
Ve a AWS Console → VPC → Your VPCs → Create VPC
2
Completa los campos
Selecciona "VPC only". Name tag: prod-vpc. IPv4 CIDR: 10.0.0.0/16. Tenancy: Default.
3
Habilitar DNS hostnames
Después de crear, selecciona la VPC → Actions → Edit VPC settings → activa Enable DNS hostnames y Enable DNS resolution.
💡
El CIDR 10.0.0.0/16 te da 65,534 IPs utilizables. Es suficiente para cualquier proyecto. Nunca uses un CIDR que se superponga con tu red local.
02

Paso 2 – Crear las Subnets

4 subnets: 2 públicas y 2 privadas en diferentes AZs

ℹ️
Las subnets NO son públicas o privadas por sí mismas — lo que las hace públicas es tener una ruta a través del Internet Gateway en su Route Table.
🔲
Crear cada subnet: VPC → Subnets → Create Subnet
1
Subnet pública A
Name: public-subnet-a · VPC: prod-vpc · AZ: us-east-1a · CIDR: 10.0.1.0/24
Después de crear: Actions → Edit subnet settings → activa Enable auto-assign public IPv4 address
2
Subnet privada A
Name: private-subnet-a · VPC: prod-vpc · AZ: us-east-1a · CIDR: 10.0.2.0/24
No activar auto-assign public IP.
3
Subnet pública B
Name: public-subnet-b · VPC: prod-vpc · AZ: us-east-1b · CIDR: 10.0.3.0/24
Activar auto-assign public IPv4.
4
Subnet privada B
Name: private-subnet-b · VPC: prod-vpc · AZ: us-east-1b · CIDR: 10.0.4.0/24
03

Paso 3 – Internet Gateway (IGW)

La puerta de entrada y salida a internet

1
Crear el IGW
VPC → Internet Gateways → Create. Name: prod-igw
2
Adjuntar a la VPC
Selecciona el IGW → Actions → Attach to VPC → selecciona prod-vpc. Un IGW solo puede estar adjunto a una VPC a la vez.
⚠️
El Internet Gateway por sí solo no hace que nada sea público. Debes crear una Route Table que dirija el tráfico 0.0.0.0/0 hacia el IGW.
04

Paso 4 – NAT Gateway

Permite a las subnets privadas salir a internet sin ser accesibles

💰
El NAT Gateway tiene costo. Para producción se recomienda uno por AZ (~$32/mes cada uno). Para desarrollo puedes usar solo uno. Una alternativa gratuita es usar NAT Instances (EC2), pero son más complejas de administrar.
1
Crear NAT Gateway en subnet pública A
VPC → NAT Gateways → Create. Name: nat-gw-a · Subnet: public-subnet-a · Connectivity type: Public · Haz clic en Allocate Elastic IP para asignar una IP fija.
2
(Producción) Crear NAT Gateway en subnet pública B
Repite el proceso. Name: nat-gw-b · Subnet: public-subnet-b. Espera a que ambos estén en estado Available antes de continuar (~1-2 min).
05

Paso 5 – Route Tables

Define a dónde va el tráfico de cada subnet

🗺️
Route Table Pública (para subnets públicas)
1
Crear
VPC → Route Tables → Create. Name: rtb-public · VPC: prod-vpc
2
Agregar ruta a internet
Selecciona la RT → Tab Routes → Edit routes → Add route: Destination 0.0.0.0/0 · Target: Internet Gateway → prod-igw
3
Asociar subnets públicas
Tab Subnet associations → Edit → selecciona public-subnet-a y public-subnet-b
🗺️
Route Tables Privadas (una por AZ)
1
Route Table privada A
Name: rtb-private-a. Ruta: 0.0.0.0/0 → Target: NAT Gateway → nat-gw-a. Asociar: private-subnet-a
2
Route Table privada B
Name: rtb-private-b. Ruta: 0.0.0.0/0 → Target: NAT Gateway → nat-gw-b. Asociar: private-subnet-b

Paso 6 – Security Groups

Firewall para cada capa de tu aplicación

🔑
Regla de oro: crea un Security Group por tipo de recurso (uno para el Load Balancer, uno para la aplicación, uno para la base de datos). Esto te permite referenciar SGs entre sí en lugar de usar IPs.
🛡️
Security Groups recomendados
SGInboundFuenteUso
sg-alb80, 4430.0.0.0/0Application Load Balancer
sg-app3000, 3001…sg-alb (el SG de arriba)Servidores Next.js / MFEs
sg-lambda—Solo outbound a sg-dbFunciones Lambda
sg-db27017 (Mongo) / 5432 (PG)sg-app, sg-lambdaBase de datos
⚠️
Para el outbound (salida), las reglas son permisivas por defecto (0.0.0.0/0). Solo restringe outbound si tienes requerimientos de compliance estrictos.
⚙️
Crear un Security Group
1
VPC → Security Groups → Create security group
Name: sg-app · VPC: prod-vpc · Description: "App servers"
2
Agregar reglas Inbound
Add rule → Type: Custom TCP · Port: 3000 · Source: sg-alb (selecciona el SG del ALB). Esto significa: "solo acepta tráfico del Load Balancer".
3
Crear los demás SGs
Repite el proceso para sg-lambda y sg-db usando los SGs anteriores como fuente.
07

Paso 7 – Verificar conectividad

Comprueba que la red está funcionando correctamente

1
Lanza una EC2 en subnet pública
EC2 → Launch instance. Selecciona public-subnet-a y sg-alb. Habilita "Auto-assign public IP". Conéctate vía SSH y verifica: curl https://checkip.amazonaws.com — debes ver una IP pública.
2
Lanza una EC2 en subnet privada
Sin IP pública. Conéctate a través de la instancia pública (bastion host) o via AWS Systems Manager Session Manager. Verifica: curl https://checkip.amazonaws.com — debes ver la IP del NAT Gateway.
3
Usa VPC Reachability Analyzer
VPC → Network Manager → Reachability Analyzer. Crea un análisis de origen (instancia pública) a destino (instancia privada). Debe indicar "Reachable".

Consideraciones para producción

Buenas prácticas adicionales

🔒 VPC Flow Logs

Activa los Flow Logs en la VPC para auditar todo el tráfico. VPC → selecciona → Flow Logs → Create. Envía a CloudWatch Logs.

🔗 VPC Endpoints

Para acceder a S3, DynamoDB, Lambda desde subnets privadas sin pasar por internet. Crea endpoints de tipo Gateway (S3/Dynamo) o Interface (otros servicios).

📊 Network ACLs

Capa adicional de seguridad a nivel de subnet (stateless). Para la mayoría de casos los Security Groups son suficientes, pero úsalos para bloquear IPs maliciosas.

💰 Costo estimado

NAT Gateway: ~$32/mes + $0.045/GB. Para ahorrar en dev, usa un solo NAT GW. En producción, uno por AZ para redundancia.
