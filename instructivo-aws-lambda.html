¿Qué es Lambda y cómo funciona?

Serverless: código sin administrar servidores

⚡
AWS Lambda ejecuta tu código en respuesta a eventos. No necesitas aprovisionar ni administrar servidores. Pagas solo por el tiempo de ejecución (primeros 1M de invocaciones por mes son gratis).

🔄 Ciclo de vida

1. Llega un evento (HTTP, timer, S3 upload…)
2. AWS instancia un contenedor
3. Ejecuta tu función
4. Devuelve el resultado
5. El contenedor se congela (warm) o destruye

⏱️ Límites importantes

Timeout máximo: 15 minutos. Memoria: 128MB a 10GB. Tamaño del paquete: 50MB (zip) / 250MB descomprimido. Disco temporal: 512MB - 10GB en /tmp.

💰 Precios

Primero 1M req/mes: gratis. Luego: $0.20 por millón de solicitudes + $0.0000166667 por GB-segundo.

🌡️ Cold Start

La primera ejecución tarda más (~100ms-1s) porque AWS debe preparar el entorno. Las siguientes son más rápidas (warm). Usa Provisioned Concurrency para eliminar cold starts en producción.

Paso 1 – IAM Role para Lambda

Los permisos que tu función necesita para operar

⚠️
Principio de mínimo privilegio: dale a tu Lambda solo los permisos que realmente necesita. Nunca uses AdministratorAccess en producción.
🔑
Crear el IAM Role
1
IAM → Roles → Create role
Trusted entity: AWS service → Use case: Lambda. Esto permite que Lambda asuma este rol.
2
Adjuntar políticas base
Busca y adjunta AWSLambdaBasicExecutionRole — permite escribir logs a CloudWatch. Si usas VPC, también adjunta AWSLambdaVPCAccessExecutionRole.
3
Nombre del rol
Name: lambda-pdf-report-role. Guarda el ARN, lo necesitarás al crear la función.
📋
Política personalizada: acceso a S3 y SES
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",       // guardar el PDF en S3
        "s3:GetObject"        // leer archivos de S3
      ],
      "Resource": "arn:aws:s3:::mi-bucket-reportes/*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ses:SendEmail",       // enviar emails con SES
        "ses:SendRawEmail"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "logs:CreateLogGroup",
        "logs:CreateLogStream",
        "logs:PutLogEvents"
      ],
      "Resource": "*"
    }
  ]
}

IAM → Roles → tu rol → Add permissions → Create inline policy → pega el JSON anterior.

Paso 3 – Estructura del código Lambda

El handler: función de entrada y salida

💻
Handler básico (Node.js)
index.mjs
// El handler es la función de entrada de tu Lambda
// event: datos del trigger (body HTTP, evento S3, etc.)
// context: información de la ejecución (timeouts, requestId, etc.)

export const handler = async (event, context) => {
  // Parsear el body si viene de API Gateway
  const body = event.body
    ? JSON.parse(event.body)
    : event;

  console.log("Event recibido:", JSON.stringify(body, null, 2));

  try {
    // Tu lógica aquí
    const resultado = await procesarSolicitud(body);

    // Respuesta compatible con API Gateway
    return {
      statusCode: 200,
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ success: true, data: resultado }),
    };
  } catch (error) {
    console.error("Error en Lambda:", error);
    return {
      statusCode: 500,
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ error: error.message }),
    };
  }
};
📁
El archivo principal debe llamarse index.mjs (ESM) o index.js (CommonJS). El handler se configura como index.handler en la consola de Lambda. Si usas ESM, el package.json debe tener "type": "module".

Paso 5 – Conectar Lambda a la VPC

Para acceder a RDS, MongoDB o recursos privados

⚠️
Conectar Lambda a una VPC incrementa el cold start (~400ms extra). Solo hazlo si necesitas acceder a recursos privados como RDS o MongoDB dentro de la VPC.
1
Lambda → Configuration → VPC → Edit
VPC: prod-vpc · Subnets: selecciona las subnets privadas (private-subnet-a, private-subnet-b). Security groups: sg-lambda
2
Verifica el IAM Role
El rol debe tener AWSLambdaVPCAccessExecutionRole para que Lambda pueda crear las ENI (Elastic Network Interfaces) en las subnets.
3
Acceso a internet desde VPC
Lambda en VPC privada accede a internet vía el NAT Gateway. Asegúrate de que la route table de la subnet privada tenga la ruta 0.0.0.0/0 → NAT GW.

Paso 7 – Lambda Layers (dependencias)

Cómo incluir librerías npm en tu función

📦
Lambda Layers permiten separar las dependencias (node_modules) del código de la función. Así el ZIP de tu función es pequeño y los layers se reutilizan entre funciones.
📦
Crear un Layer con dependencias npm
# 1. En tu máquina local, crea la estructura requerida
mkdir -p nodejs/node_modules
cd nodejs

# 2. Instala las dependencias en la carpeta nodejs/
npm install pdfkit @aws-sdk/client-s3 @aws-sdk/client-ses

# 3. Vuelve al directorio padre y crea el ZIP
cd ..
zip -r dependencies-layer.zip nodejs/

# El ZIP debe contener: nodejs/node_modules/pdfkit/...
1
Subir el Layer
Lambda → Layers → Create layer. Name: pdf-dependencies · Sube el ZIP · Compatible runtimes: Node.js 20.x
2
Adjuntar a la función
Lambda → tu función → Layers → Add a layer → Custom layers → selecciona pdf-dependencies

Paso 8 – Desplegar el código con ZIP

Sube tu función desde la terminal

🚀
Deploy manual con AWS CLI
# 1. Instala AWS CLI si no lo tienes
brew install awscli       # macOS
aws configure             # introduce tu Access Key ID y Secret

# 2. En la carpeta de tu función (donde está index.mjs)
zip -r function.zip index.mjs

# 3. Sube el ZIP a Lambda
aws lambda update-function-code \
  --function-name generate-pdf-report \
  --zip-file fileb://function.zip \
  --region us-east-1

# 4. Invoca la función para probar
aws lambda invoke \
  --function-name generate-pdf-report \
  --payload '{"test": true}' \
  --cli-binary-format raw-in-base64-out \
  response.json

cat response.json
🚀
Para proyectos más grandes, usa AWS SAM o Serverless Framework que automatizan el proceso de empaquetado y despliegue con un solo comando sam deploy o serverless deploy.

Monitoreo y Logs con CloudWatch

Observa el comportamiento de tu función en producción

1
Ver logs en tiempo real
Lambda → Monitor → View CloudWatch logs. Cada invocación genera un log stream. Busca el requestId para rastrear una ejecución específica.
2
Métricas clave
Lambda → Monitor: Invocations (veces ejecutada), Duration (tiempo), Errors (fallos), Throttles (límite de concurrencia alcanzado).
3
Alertas con CloudWatch Alarms
CloudWatch → Alarms → Create alarm. Configura una alerta cuando los Errors superen 5 en 5 minutos. Envía notificación a SNS → Email.
