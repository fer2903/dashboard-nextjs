Arquitectura Multi-zone
Cómo se comunican el host y los MFEs

El patrón Multi-zone de Next.js permite que múltiples apps Next.js independientes se vean como una sola desde el navegador. El host delega rutas a los MFEs vía rewrites.

localhost:3000 → Host (dashboard-nextjs)
localhost:3000/dashboard/transactions ──rewrite──▶ localhost:3001
localhost:3000/dashboard/orders ──rewrite──▶ localhost:3002
localhost:3000/dashboard/reports ──rewrite──▶ localhost:3003
localhost:3000/api/* → MongoDB (accesible desde todos los MFEs vía CORS)
ℹ️ La URL en el navegador siempre muestra el puerto del host (3000). El usuario nunca sabe que existe un MFE en otro puerto — todo parece una sola app.
①
Paso 1 — Crear el proyecto MFE
Inicializar Next.js con los archivos de configuración correctos

Elige un nombre para tu módulo. En este ejemplo usamos orders-mfe en el puerto 3002.

1
Crear la carpeta del MFE (dentro del monorepo o fuera)
# Dentro del monorepo (recomendado)
cd /ruta/a/dashboard-nextjs
mkdir orders-mfe && cd orders-mfe

# O como proyecto independiente
mkdir ~/proyectos/orders-mfe && cd ~/proyectos/orders-mfe
2
Crear package.json
{
  "name": "orders-mfe",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "dev":   "next dev -p 3002",
    "build": "next build",
    "start": "next start -p 3002"
  },
  "dependencies": {
    "next":       "^15.3.1",
    "react":      "^19.0.0",
    "react-dom":  "^19.0.0"
  },
  "devDependencies": {
    "typescript":          "^5",
    "@types/node":         "^20",
    "@types/react":        "^19",
    "tailwindcss":         "^4",
    "@tailwindcss/postcss": "^4"
  }
}
3
Crear next.config.ts — la parte más crítica
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  // 🔑 CLAVE: basePath hace que TODAS las rutas del MFE
  //    queden automáticamente bajo este prefijo.
  //    Debe coincidir exactamente con el rewrite del host.
  basePath: "/dashboard/orders",

  // Permite que el host (localhost:3000) embeba este MFE
  async headers() {
    return [{
      source: "/:path*",
      headers: [
        { key: "Access-Control-Allow-Origin",
          value: "http://localhost:3000" }
      ]
    }];
  },
};

export default nextConfig;
4
Crear .env.local — URL de la API del host
# .env.local
NEXT_PUBLIC_API_URL=http://localhost:3000
⚠️ En producción este valor debe apuntar al dominio real del host. No lo hardcodees en el código.
5
Crear tsconfig.json
{
  "compilerOptions": {
    "target": "ES2017",
    "lib": ["dom", "dom.iterable", "esnext"],
    "allowJs": true,
    "skipLibCheck": true,
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "module": "esnext",
    "moduleResolution": "bundler",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "jsx": "preserve",
    "incremental": true,
    "plugins": [{ "name": "next" }],
    "paths": { "@/*": ["./app/*"] }
  },
  "include": ["next-env.d.ts", "**/*.ts", "**/*.tsx"],
  "exclude": ["node_modules"]
}
6
Crear postcss.config.mjs (para Tailwind v4)
const config = {
  plugins: { "@tailwindcss/postcss": {} }
};
export default config;

Los archivos mínimos para que el MFE funcione
1
app/globals.css — copiar los tokens de diseño del host
@import "tailwindcss";

:root {
  --primary:        #4f46e5;
  --background:     #F4F6F8;
  --surface:        #ffffff;
  --text-primary:   #212B36;
  --text-secondary: #637381;
  --text-disabled:  #919EAB;
  --divider:        rgba(145, 158, 171, 0.24);
  --sidebar-bg:     #1C2536;
  --shadow-card:    0 0 2px 0 rgba(145,158,171,0.20),
                    0 12px 24px -4px rgba(145,158,171,0.12);

}

body {
  background-color: var(--background);
  color: var(--text-primary);
}
💡 Usar los mismos tokens CSS garantiza que el MFE se vea idéntico al host cuando se integra vía Multi-zone.
2
app/layout.tsx — layout raíz con sidebar
import "./globals.css";

export default function RootLayout({
  children
}: { children: React.ReactNode }) {
  return (
    <html lang="es">
      <body style={{ display: "flex", minHeight: "100vh" }}>
        {/* Sidebar del MFE */}
        <Sidebar />
        {/* Contenido principal */}
        <main style={{ flex: 1, backgroundColor: "var(--background)" }}>
          <TopBar />
          {children}
        </main>
      </body>
    </html>
  );
}
3
app/page.tsx — página principal del módulo
"use client";

export default function OrdersPage() {
  const API = process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:3000";

  // Aquí va la lógica del módulo
  return (
    <div className="p-6">
      <h1>Módulo de Órdenes</h1>
    </div>
  );
}
ℹ️ Con basePath: "/dashboard/orders", la ruta app/page.tsx responde en /dashboard/orders. No necesitas crear carpetas intermedias.

Estructura mínima de archivos:

orders-mfe/

├── package.json
├── postcss.config.mjs
└── tsconfig.json

Paso 3 — Integrar en el Host
Cambios en dashboard-nextjs para enrutar al MFE
1
Agregar rewrite en next.config.ts del host
const nextConfig: NextConfig = {
  async rewrites() {
    return [
      // MFE existente — Transactions (puerto 3001)
      {
        source:      "/dashboard/transactions/:path*",
        destination: "http://localhost:3001/dashboard/transactions/:path*",
      },
      // ✅ NUEVO MFE — Orders (puerto 3002)
      {
        source:      "/dashboard/orders",
        destination: "http://localhost:3002/dashboard/orders",
      },
      {
        source:      "/dashboard/orders/:path*",
        destination: "http://localhost:3002/dashboard/orders/:path*",
      },
    ];
  },
};
⚠️ Siempre agrega dos entradas por MFE: una para la ruta exacta (/dashboard/orders) y otra para sub-rutas (/dashboard/orders/:path*).
2
Agregar CORS a la API del host si el MFE la necesita
// app/api/orders/route.ts (o el endpoint que use el MFE)
const CORS_HEADERS = {
  "Access-Control-Allow-Origin":  "http://localhost:3002",
  "Access-Control-Allow-Methods": "GET, POST, PUT, DELETE, OPTIONS",
  "Access-Control-Allow-Headers": "Content-Type, Authorization",
};

export async function OPTIONS() {
  return new NextResponse(null, { status: 204, headers: CORS_HEADERS });
}

export async function GET() {
  await connectDB();
  const data = await Order.find().sort({ createdAt: -1 });
  return NextResponse.json(data, { headers: CORS_HEADERS });
}
✅ CORS solo es necesario si el MFE llama directamente a la API del host (localhost:3000/api/...). Las peticiones que pasan por el rewrite no necesitan CORS.
3
Crear página fallback en el host (opcional pero recomendado)
// app/dashboard/orders/page.tsx
// Solo se muestra cuando el MFE NO está corriendo.
// El rewrite en next.config.ts tiene precedencia cuando el MFE está activo.

export default function OrdersFallbackPage() {
  return (
    <div>
      <p>El MFE de Orders no está disponible.</p>
      <p>Inicia el servidor: cd orders-mfe && npm run dev</p>
    </div>
  );
}

Paso 4 — Levantar y probar
Comandos para iniciar host y MFE
1
Terminal 1 — Host
cd dashboard-nextjs
# Primera vez o tras cambios en next.config.ts:
rm -rf .next && npm run dev
# Resto de veces:
npm run dev
2
Terminal 2 — MFE (primera vez)
cd orders-mfe
npm install
npm run dev
3
Verificar en el navegador
# ✅ Con MFE activo → muestra el módulo Orders
http://localhost:3000/dashboard/orders

# ✅ Sin MFE → muestra la página fallback del host
http://localhost:3000/dashboard/orders
